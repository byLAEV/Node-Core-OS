# Node Core OS — Termux compatibility profile

**Status:** initial implementation / experimental.  
**Target:** native Termux on Android, ARM64 first.

This profile is separate from GNU/Linux desktop support. It detects and documents
Termux-specific paths, package management, Android integration and runtime limits.

## Lobby prototype

The local Lobby server uses only Python's standard library. It binds exclusively to
`127.0.0.1`, uses port 8765 by default, and never listens on a LAN interface.
A random local token is generated and stored with mode 0600 for future authenticated
administrative APIs. The initial UI is informational and read-only.

HTTPS is attempted using a self-signed localhost certificate generated by OpenSSL.
Because Android browsers do not automatically trust that certificate, a browser
warning may appear. The launcher prefers HTTPS and falls back to HTTP on loopback
when TLS cannot be started. HTTP loopback is not encrypted; do not expose it to LAN
or use it for remote access.

## Android home-screen entry

The server cannot be started by an ordinary PWA icon after Android has stopped
Termux. The supported initial launch mechanism is a Termux:Widget shortcut that runs
`launcher.sh`, starts the local server, then opens the local URL in the browser.
Install Termux:Widget from the same trusted Termux distribution source as Termux,
create its home-screen widget/shortcut, and select the Node Core Lobby script.
A browser PWA installation may be offered as a second-stage convenience, but it
does not replace the Termux launcher when the server is stopped.

Android battery management may stop background processes. This prototype does not
claim persistent background service guarantees.

## Install prototype files

From a checkout of this repository in Termux:

```bash
bash compatibility/termux/install-lobby.sh
```

Then launch:

```bash
bash "$HOME/.shortcuts/node-core-lobby"
```

The installer creates a Termux:Widget shortcut script. It does not install or modify
Node Core OS itself and does not modify shell startup files.

## Security boundaries

- Loopback-only bind address; no LAN exposure.
- No root, `sudo`, or Android privileged operations.
- Self-signed TLS is not equivalent to a browser-trusted certificate.
- HTTP fallback is limited to `127.0.0.1`.
- Initial dashboard is read-only; install/update/fix actions are not wired.
- Do not add state-changing APIs without authentication, CSRF/origin protections,
  explicit user confirmation, audit logging and tests.

## Validation

Run on a real Termux ARM64 device. Repository-side syntax checks are not a substitute
for device tests. Record Android version, Termux source/version, architecture,
Python/OpenSSL versions, browser and results before marking this profile VERIFIED.
