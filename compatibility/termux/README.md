# Node Core OS — Termux compatibility profile

**Status:** experimental; physical-device validation is ongoing.  
**Target:** native Termux on Android, ARM64 first.

## Local Lobby inventory

The Lobby server uses Python's standard library and binds exclusively to
\`127.0.0.1:8765\`. It prefers HTTPS with a self-signed localhost certificate
generated by OpenSSL. In Termux, the CLI is supplied by \`openssl-tool\`; the
installer checks the executable and attempts to install that package if absent.
HTTP is used only as a loopback fallback.

### Read-only API

- \`GET /health\`: server status and actual transport.
- \`GET /api/status\`: current service and Node Core OS detection.
- \`GET /api/diagnostics\`: full diagnostic report (compatibility alias).
- \`GET /api/report\`: full read-only inventory for the Lobby UI.

The report includes Android/Termux, kernel, architecture, Python, shell and
terminal metadata; Node Core OS installation and version detection from the
canonical \`~/.node-core\` data directory; separate repository checkout detection;
installed dpkg packages (maximum 400); executable availability; interface states,
DNS resolution, outbound TCP 443 and local Kubo RPC/gateway/Lobby checks; and
bounded directory structures for HOME, \`~/.node-core\`, known checkouts, Termux
PREFIX and shortcuts.

### Privacy and safety

The report is read-only. It does not read file contents, run shell startup files,
install/remove packages, change permissions or alter network settings. It excludes
SSH/GnuPG, keys, private credentials, wallets, identity material, caches and Git
internals. Symlinks are not followed. Storage and IPFS directory contents are not
traversed. Proxy presence may be reported, but proxy values are never exposed.
Package and directory output are bounded. DNS/TCP checks have short timeouts and
may be inconclusive on restricted networks.

Installation/update/repair actions remain disabled until they have separate
authorization, audit logs, rollback behavior and tests.

## Android home-screen entry

Termux:Widget is the initial launcher mechanism. A plain PWA icon cannot start
Termux after Android has stopped its process. Android battery management may
stop background processes; persistent execution is not guaranteed.

## Install

From a repository checkout inside native Termux:

\`\`\`bash
bash compatibility/termux/install-lobby.sh
\`\`\`
